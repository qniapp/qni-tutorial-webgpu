# 状態バーの再実行ボタン

`run-button` 属性のある埋め込みだけ、青い状態バーの右端に円形の矢印を表示する。
枠外の丸い再生ボタンは削除した。属性がなければ再実行ボタンは表示しない。
「Qniで開く」のタブに高さ 44px が必要なので、
枠の高さとタブの配置は変えない。

`run-button` という属性名は表示の指定として維持し、`showRestartButton` と `onRestart` を埋め込み API に渡す。
`qni-webgpu.ref` は、この API を追加する [qni-webgpu の PR #64](https://github.com/qniapp/qni-webgpu/pull/64) の最新コミット `51a14e48a4334bee97a638e598dd996a23d3de0a` に固定する。
読み込み中、切断後、破棄済みのランナーからの通知は受け付けない。
編集済みの `circuitJSON()` が `circuit` 属性と同じなら `restart()`、
異なるなら `setAttribute('circuit', circuitJSON)` で再起動する。従来のクリック処理と同じである。
編集後の再実行では `circuit` 属性が編集済みの回路で上書きされる。
比較は文字列の完全一致なので、JSON の空白などが異なる場合も属性を更新する。

`run-button` の追加・削除は、現在の回路を保持してランナーを起動し直す。
再実行や属性の切り替えでは、ランナーの操作履歴は消える。

上流の描画では、狭い画面で状態数と再実行ボタンを優先し、状態バー左側の量子ビット数を省く場合がある。
図形は egui で描き、既存の状態バーの Flexoki 色とツールバーの線幅に合わせる。
ホバー説明とボタン情報の名前は「量子回路を実行」で、Enter と Space に対応する。
このリポジトリでも実際の埋め込みを使うキーボード操作テストを追加し、ローカルで検証した。
GitHub の継続的インテグレーションでは型検査とビルドを実行する。

`docs/porting.md` の枠外の実行ボタンに関する検証記録は変更前の履歴であり、現在の仕様は本書に従う。
