# Orbit プロンプトの書き方

このチュートリアルの復習問題（`<orbit-prompt>`）を書く・直す・レビューするときの指針です。Andy Matuschak「How to write good prompts: using spaced repetition to create understanding」（https://andymatuschak.org/prompts/ ）の考え方をもとにしています。本文・チェックリスト・例はすべて独自に書いたものです。参照した文章を写さず、自分の言葉で要約してください。

## なぜこれらの規則があるのか

プロンプトはメモではなく課題です。学習効果は、答えを記憶から思い出す努力を、間隔を広げながら繰り返すことで生まれます。読み返すだけよりも、記憶から引き出す練習のほうが定着を促します。以下の規則はすべて、この「思い出す行為」を守るためのものです。学習者が狙いどおりの内容を毎回思い出す必要があり、思い出せたかどうかを正直に判定できなければなりません。

答えが表示されるのは、学習者が思い出そうとした後です。答えは確認される対象であり、ヒントではありません。曖昧な問題文を答えの側で補おうとしないでください。

## 1 問ずつのチェックリスト

すべてのプロンプトを以下で確認します。各項目は PASS か FAIL で判定し、FAIL は ID で示します。

| ID | 原則 | English | PASS の条件 |
|---|---|---|---|
| P1 | 一点集中 | Focused | 1 つの細部だけを狙っている。事実が 2 つあるなら 2 問に分ける。 |
| P2 | 的確さ | Precise | どんな答えを求めているかが問題文からはっきり分かる。曖昧な問いには曖昧な想起しか返ってこない。 |
| P3 | 一貫した想起 | Consistent | 何か月後に見ても、毎回同じ答えが正解になる。気分や読み方で答えが変わらない。 |
| P4 | 答えられる | Tractable | 学んだ人ならたいてい答えられる。手がかりは対象を絞り込むが、答えそのものは明かさない。 |
| P5 | 努力を要する | Effortful | 答えは記憶から出す必要がある。問題文の言い回しや文法、隣のプロンプトと共通するパターンから推測できない。 |
| P6 | 短く自己採点できる答え | Short, self-gradable answer | 答えの核心が短く、一目で正誤を判定できる。説明は任意で、見て分かるように分け、覚えるべき事実を増やさない。 |
| P7 | 二択にしない | Not binary | はい/いいえ、AかBかの問いにしない。「なぜ」「例」「そこから何が言えるか」に言い換える。 |
| P8 | 列挙させない | No list recall | 「すべて挙げよ」にしない。固定のリストは分割するか、項目ごとに cloze を 1 つ作る。正解が多数ある開いた集合から、任意の 1 つを隠さない。 |
| P9 | 文脈なしで通じる | Stands alone | 何か月後にページを閉じた状態で読んでも通じる。基底・規約・記法・範囲が答えを左右するなら明記する。 |
| P10 | 内容の正しさ | Correct | 記述・数式・符号がすべて正しい。暫定的な主張や議論のある主張には留保と出典を付ける。 |
| P11 | マークアップの正しさ | Valid markup | 実在する属性だけを使い、TeX の対応が取れ、属性値の中の引用符がエスケープされ、既存の属性が保たれている。 |
| P12 | 学ぶ価値 | Relevant | 読者にとって意味のある学習目標につながり、孤立した豆知識を覚えさせるだけになっていない。 |

すべての条件を満たせば PASS、満たさない項目は FAIL です。網羅性は別に、次のセット単位で確認します。

## セット全体のチェックリスト

ページやトピックのプロンプト全体について、1 問ずつのチェックとは別に判定します。

| ID | 原則 | English | PASS の条件 |
|---|---|---|---|
| S1 | 複数の角度 | Multiple angles | 意味のある考え方には、定義だけでなく複数の方向から問いがある。 |
| S2 | 概念のレンズ | Lenses used | 概念には、合う範囲でレンズを使う。性質、近い概念との比較、部分と全体、原因と結果、意義。 |
| S3 | 手順の要所 | Procedures cut well | 手順は全体を暗唱させず、要となる用語、次のステップへ移るきっかけ、分岐の条件、各ステップがある理由で扱う。 |
| S4 | 使う場面 | Use opportunities | 経験則には、状況から行動を問うプロンプトがあり、使いどころに気づけるようにしている。 |
| S5 | 学習者に合った粒度 | Fits the learner | 範囲が学習者のまとまりの大きさに合っている。ある人には 1 単位でも、別の人には分解が必要なことがある。 |
| S6 | 小さく役立つ集合 | Small and useful | 重要な点に絞った少数のプロンプトで、網羅的な豆知識の集まりではない。 |

## プロンプトの書き方

元の文章を写さず、解釈してつなげてください。プロンプトを書くと、自分がまだ理解していない点が見えてきます。答えを書く前にその穴を埋め、事実を確認してください。

概念の知識では、それが何に似ているか、近い概念とどう違うか、何の一部で何からできているか、何を引き起こし何から生じるか、なぜ重要かを問います。定義だけを問うプロンプトは、名前を確かめるだけで考え方そのものは確かめません。

難しすぎる問いには、答えを明かさない手がかりを加えます。図や既知の知識とのつながり、印象に残る連想も役立ちます。覚え方の補助は答えの後に任意の説明として置き、想起の代わりにしないようにします。

問題数を減らすために、異なる細部を一問へ詰め込まないでください。有用な知識は必要に応じて分割し、明らかに推測できる内容や、学ぶ意味を感じない内容は省きます。

手順では、実際に忘れやすい部分を選びます。ステップを指す用語、ステップが終わった合図、分岐を決める条件、そのステップがある理由です。

経験則では、状況を示して何をするかを問うプロンプトを書きます。実際の場面で正しい手が思い浮かぶようにするのが狙いです。ただし、これや、考えを意識に留めておくための創造的・発展的なプロンプトは、想起練習ほど効果が確かめられていません。開いた問いが自動的に想起のプロンプトになるわけでもありません。毎回新しい答えを求めるなら、安定した一つの答えを強化する復習問題ではなく、創造的な課題として区別します。通常の復習問題には P3 と P6 を適用します。

説明を添えたいときは、答えの核心の後に置いて印を付けます（例: `（理由: ...）`）。学習者が採点するのは核心の答えだけです。

まず最も大事な点について少数のプロンプトを書き、理解が深まるにつれて増やします。後から、解いていて苛立つプロンプトや曖昧なプロンプト、表面的なパターンで簡単になってしまったプロンプトは直し、学習者にとってもう重要でないプロンプトは削除します。

## Orbit のマークアップ

プロンプトはレビューエリアの中に置きます。問題と答えの形式です。

```html
<orbit-reviewarea>
  <orbit-prompt question="..." answer="..."></orbit-prompt>
</orbit-reviewarea>
```

cloze 形式では、波かっこで囲んだ部分が隠れます。

```html
<orbit-prompt cloze="... {隠す部分} ..."></orbit-prompt>
```

属性を作らないでください。ページを編集するときは、各要素にすでにある属性をそのまま残し、`$|0\rangle$` のような TeX も崩さないでください。表示側が複数の穴を意図どおりに扱うと確認できていない限り、cloze 1 つにつき穴は 1 つにします。

## 良い例と悪い例

例はすべて量子計算から取っています。悪い例の後に直した例と、FAIL になる ID を示します。

### 二択の問いを、説明を問う形に直す

悪い例（P7, P5）:

```html
<orbit-prompt question="グローバル位相は測定で検出できますか?" answer="できない"></orbit-prompt>
```

良い例:

```html
<orbit-prompt question="$e^{i\theta}|\psi\rangle$ と $|\psi\rangle$ をどんな測定でも区別できないのはなぜですか?" answer="どの結果の確率も絶対値の 2 乗で、$|e^{i\theta}|=1$ なので、確率がすべて一致するからです。"></orbit-prompt>
```

### 1 問に入った 2 つの事実を分ける

悪い例（P1, P6）:

```html
<orbit-prompt question="行列の随伴とは何ですか? また、ユニタリ $U$ では $U^\dagger U$ は何になりますか?" answer="共役転置。単位行列"></orbit-prompt>
```

良い例:

```html
<orbit-prompt question="行列 $M$ から随伴 $M^\dagger$ を作るには、どの 2 つの操作をしますか?" answer="転置して、すべての成分の複素共役を取ります。"></orbit-prompt>
<orbit-prompt question="ユニタリ $U$ について、$U^\dagger U$ は何ですか?" answer="単位行列 $I$ です。"></orbit-prompt>
```

### 問題文に答えが書いてあるものを直す

悪い例（P5）:

```html
<orbit-prompt question="振幅の絶対値を 2 乗するボルンの規則によると、正規化された状態 $\alpha|0\rangle+\beta|1\rangle$ で 0 が出る確率は?" answer="$|\alpha|^2$"></orbit-prompt>
```

良い例:

```html
<orbit-prompt question="正規化された状態 $\alpha|0\rangle+\beta|1\rangle$ を計算基底で測定したとき、0 が出る確率は?" answer="$|\alpha|^2$（理由: ボルンの規則により、振幅のノルムの 2 乗になる）"></orbit-prompt>
```

### 列挙させる問いを cloze に分ける

悪い例（P8, P1）:

```html
<orbit-prompt question="$X$、$Y$、$Z$ はそれぞれ $|0\rangle$ をどう変えますか?" answer="$|1\rangle$、$i|1\rangle$、$|0\rangle$"></orbit-prompt>
```

良い例（固定のリストなので、項目ごとに cloze を 1 つ作る）:

```html
<orbit-prompt cloze="$X$ ゲートは $|0\rangle$ を {$|1\rangle$} に移す"></orbit-prompt>
<orbit-prompt cloze="$Y$ ゲートは $|0\rangle$ を {$i|1\rangle$} に移す"></orbit-prompt>
<orbit-prompt cloze="$Z$ ゲートは $|1\rangle$ を {$-|1\rangle$} に移す"></orbit-prompt>
```

開いた集合と比べてください。`cloze="$|0\rangle$ を重ね合わせにするゲートの例は {$H$} です"` は P3 と P8 で FAIL です。当てはまるゲートがたくさんあるので、正しく思い出しても不正解と判定されることがあります。代わりに、特定のゲートが何をするか、そのゲートのどの性質がなぜその用途に向いているのかを問います。

### 文脈不足を、測定基底を明記して直す

悪い例（P9, P3）:

```html
<orbit-prompt question="$|+\rangle$ を測定して 1 が出る確率は?" answer="1/2"></orbit-prompt>
```

計算基底なら 1/2 ですが、$X$ 基底で結果 1 を $|-\rangle$ とするなら 0 です。答えが 1 つに決まりません。

良い例:

```html
<orbit-prompt question="$|+\rangle$ を計算基底で測定したとき、1 が出る確率は?" answer="1/2"></orbit-prompt>
```

### 手順全体を、状況から行動を問う形に直す

悪い例（P1, P6, S3）:

```html
<orbit-prompt question="ハードウェアで X 基底の測定をする方法を説明してください" answer="（ゲート、測定、結果の読み取りにわたる数ステップ）"></orbit-prompt>
```

良い例:

```html
<orbit-prompt question="計算基底で測定する直前に $H$ を適用すると、元の状態の $X$ 基底での測定結果を読めるのはなぜですか?" answer="$H$ は $|+\rangle$ を $|0\rangle$ に、$|-\rangle$ を $|1\rangle$ に移すため、結果 0 が +、結果 1 が − を表すからです。"></orbit-prompt>
```

## 既存プロンプトの監査手順

1. まずページ全体を読み、何を教えていてどんな記法を使っているかを把握します。
2. プロンプトを 1 つずつ切り離して見ます。何か月後に、ページを閉じた状態で出会う学習者を想像します。
3. 偽陽性を確認します。言い回し、文法、答えを明かす手がかり、隣のプロンプトと共通するパターンから、内容を知らなくても正解できてしまわないか。
4. 偽陰性を確認します。問題文が曖昧、文脈が足りない、正解が複数あるなどの理由で、内容を知っている人が不正解と判定されないか。
5. P1〜P12 を確認します。数式・符号・係数は既存の答えを信用せず、自分で検算します。
6. マークアップを保ちます。意図した変更以外は、既存の属性・TeX・エスケープを 1 バイトも変えません。
7. プロンプトごとに記録します。
   - ページ
   - 変更前: 問題と答えの全文、または cloze の全文
   - 変更後: 置き換え後の全文、または「維持」「削除」
   - 理由: FAIL した ID と 1 文の説明、または維持した理由
8. ページごとと合計で件数を報告します。維持、修正、分割、削除、追加。
9. S1〜S6 は各ページのセットについて別に確認し、網羅性の不足は 1 問ずつの結果とは分けて報告します。
